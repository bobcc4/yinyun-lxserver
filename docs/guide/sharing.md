# 歌单与音源分享

## 音云服务端之间分享歌单

Web 播放器同时支持同一服务端的用户分享，以及把歌单分享给另一台音云服务端；跨服务端功能不依赖原版洛雪客户端，也不会传输音频文件。

### 配置公网访问地址

管理员在后台 **系统配置 → 公网访问地址** 中填写外部可访问的完整地址，例如 `https://music.example.com:16666`。不要填写 `/music`、`/admin` 或 `/rest` 等路径。未配置公网访问地址时，跨服务端操作仍可导出 JSON，但生成分享链接会提示先完成配置。

### 分享方

1. 登录 Web 播放器，在左侧自建歌单旁点击“跨服务端分享或导出 JSON”按钮。
2. 选择“生成分享链接”或“导出 JSON”。生成链接需要已经配置公网访问地址。
3. 将链接或 JSON 文件发送给对方。

分享包只包含歌名、歌手、平台和稳定歌曲 ID、专辑、时长等重新匹配所需信息，不包含密码、Token、代理、音频 URL、本地路径或缓存文件。分享链接是只读的，创建者可以在后续撤销。

### 接收方

1. 登录自己的音云 Web 播放器，进入 **设置 → 歌单分享**。
2. 选择“导入分享链接”，或者选择“导入歌单文件”加载 JSON 文件。
3. 查看导入预览，确认本地命中、在线可用和未匹配的数量后，点击“确认导入”。

确认后会在接收方当前账户创建一个普通歌单，歌单中的全部歌曲都会保留。接收方本地已经存在的歌曲不会复制或移动，而是在播放时优先使用本地文件；没有本地文件的歌曲则保留在线平台信息，按接收方可用音源解析。无法匹配的歌曲也会保留在歌单中，便于后续处理。

导入不会覆盖已有歌单；如果名称重复，系统会自动追加序号。跨服务器分享不需要两台服务器共享数据目录，也不会把 A 服务器的音源脚本、用户凭据或配置传给 B。

### 匹配规则与限制

- 优先按同平台歌曲 ID、Hash 等稳定标识匹配。
- 没有稳定 ID 时，仅使用同平台的歌名、歌手、专辑和时长进行精确匹配。
- 不会使用模糊匹配自动替换歌曲，避免导入同名但不是同一首的结果。
- 分享链接默认有效 30 天，单个分享包最多 10000 首歌曲、2 MB。
- 跨服务器导入需要接收方服务器能够访问分享链接。使用 Lucky 等反向代理时，上游应指向服务端根地址（例如 `http://192.168.10.108:9527`），不要配置成旧的 `/music` 子路径，并至少放行以下路径：
  - `/share/playlist/*`：分享链接预览页。
  - `/api/v1/playlist-shares/*`：跨服务端读取分享数据。

分享链接用于音云服务端之间交换，不提供直接唤起官方洛雪客户端的 `lxmusic://` 导入。洛雪导出的文件可以按下面的方法单向导入音云。

## 导入洛雪 LXMC / JSON 歌单

从 v1.7.4 起，音云支持读取洛雪导出的 `.lxmc` 压缩备份与歌单 `.json`。

1. 在洛雪中导出单个歌单，或在备份设置中导出全部歌单。
2. 登录音云 Web 播放器，打开 **设置 → 歌单分享 → 导入歌单文件**，选择文件。
3. 查看歌单名称、总歌曲数、可导入数量及跳过原因，展开“歌曲预览”检查内容。
4. 文件包含多个歌单时，勾选需要的歌单，再点击“确认导入”。

### 导入范围

- 支持 `playListPart` / `playListPart_v2` 单歌单、`playList` / `playList_v2` 全部歌单和 `allData` / `allData_v2` 完整备份中的歌单。
- 完整备份只读取歌单，不恢复设置、账户、音源或下载任务；纯设置文件不能导入为歌单。
- 每个选中的歌单创建为当前账户的普通歌单；原“我的收藏”也作为新歌单创建，不覆盖音云现有收藏。同名歌单自动追加序号。
- 保留 QQ、网易云、酷我、酷狗、咪咕的有效歌曲编号、顺序、专辑及音质信息。音频不在备份文件中，在线播放仍需要当前音云账户拥有可用音源。
- 只导入具备受支持的在线平台、歌曲 ID 和歌名的条目。洛雪本地歌曲的编号通常是原电脑文件路径，不是在线平台 ID，因此跳过；其他缺失有效信息的条目也会提示并跳过，不自动搜索匹配，不创建待匹配歌曲。没有可导入歌曲的歌单不可勾选。
- 不恢复官方 PC / 安卓客户端实时同步接口，也不会将音源脚本同步到官方客户端。

### 文件限制

上传最多 8 MB，解压后最多 16 MB；单文件最多 200 个歌单、30000 首歌曲，单歌单最多 10000 首。转换后的每个歌单包不超过 2 MB，超限请在洛雪中拆分导出。预览最多显示每个歌单前 200 首歌曲及前 100 条跳过原因，导入使用完整的有效歌曲列表。

导入多个歌单时逐个保存；发生错误后显示已完成项目和失败原因，重试只处理未完成歌单，不重复导入已成功的项目。

V1 支持两种不同的分享：所有用户之间的歌单邀请，以及管理员向其他用户提供自定义音源。

## 歌单分享开关

每个用户都必须在 **设置 -> 歌单分享** 中主动开启分享。开启表示：

- 允许向其他用户发送自己的歌单。
- 允许接收其他用户发来的歌单邀请。

如果接收方未开启，发送时会提示对方不接受分享。管理员和普通用户遵循相同规则。

## 分享歌单

1. 在左侧自建歌单旁点击分享按钮。
2. 输入对方用户名，用户名不区分大小写。
3. 服务器验证双方设置后创建邀请。
4. 接收方登录时看到待处理弹窗，也可从设置中打开待处理列表。
5. 接收方选择接受或拒绝。

接受后，服务器把歌单内容复制到接收方的收藏歌单。拒绝则不写入。之后双方歌单彼此独立，一方修改不会实时改变另一方副本。

## 文件空间占用

分享行为只复制歌单记录，不复制音频文件，因此分享本身不会占用双倍音乐空间。

如果接收方之后选择“下载到服务器”，V1 会写入接收方自己的 `/music/<用户名>`，通常会形成另一份物理文件并额外占用空间。V1 没有跨用户内容寻址去重仓库。

## 可分享歌曲的条件

歌单跨客户端同步需要平台 ID。手动放入本地目录且未绑定平台 ID 的歌曲不能作为可同步歌曲加入歌单。接收方还需要可用音源才能在线解析和播放这些记录。

## 音源分享

音源分享由管理员执行：

1. 管理员登录 Web 播放器并打开自定义源管理。
2. 在自己的源卡片点击分享。
3. 选择全部用户或指定用户后保存。
4. 接收用户重新登录或刷新源列表后即可使用。

管理员可以随时调整接收用户或撤销分享。共享的是完整脚本能力和使用权，不会向普通用户透露管理后台密码。

共享音源会展示脚本支持的全部平台。管理员对自己音源的平台选择不会传递给接收者；每个接收者可以独立勾选自己要使用的平台，且不能修改原脚本。平台选择会同时约束 Web 播放、下载、自动换源和 Subsonic 播放。

## 权限边界

- 用户只能发送自己拥有的歌单。
- 接收方必须明确接受，发送方不能直接写入对方歌单。
- 普通用户不能修改管理员共享的源。
- 普通用户可以独立调整共享源的平台开关，不会影响管理员或其他用户。
- 分享不会绕过平台版权、会员权限或音源脚本本身的限制。
